# Developing the JNVCKM site

How the site is built, edited, checked and deployed. For what the site is, see
[README.md](./README.md). Rules for agents and contributors are in
[AGENTS.md](./AGENTS.md); the design system is in [DESIGN.md](./DESIGN.md).

## Stack

| Concern | Choice |
| --- | --- |
| Framework | Astro 7, static output |
| Interactivity | Svelte 5 islands (one island: the contributions filter) |
| Styling | Plain CSS with custom properties; no framework |
| Icons | `lucide-astro` / `lucide-svelte` |
| Fonts | Self-hosted via Fontsource: Arvo, Mukta |
| Content | JSON in `content/`, edited with Sveltia CMS at `/admin/` |
| Hosting | Cloudflare Pages, project name `jnvckm` |
| Package manager | Bun |

## Commands

```bash
bun install
bun dev                 # http://localhost:4321
bun run check           # TypeScript gate; must be clean
bun run build           # social cards + -> dist/
bun run preview         # serve the build
bun run verify          # browser verification against dist/
bun run verify --shots  # ...and write screenshots/
bun run format          # prettier
bun run images          # regenerate WebP derivatives from originals/
bun run logo            # regenerate logo mark, favicons and og-default
```

`bun run build` first runs `scripts/build-og.mjs`, which writes a 1200×630 JPEG
twin of every photograph to `public/og/` so link scrapers get a format they all
render. That directory is generated and gitignored.

`bun run verify` builds nothing: run `bun run build` first. It drives a real
Chromium (system `chromium`; override with `CHROME_PATH`) and fails on any
console error, unhydrated island, broken image, horizontal overflow at
320/390/1440, skipped heading level, low-contrast text, over-long measure, a
slop-audit hit, a missing nav link, a 404 internal link, a filter that does not
change the visible count, or a CMS admin that fails to mount.

## Editing content

Content is JSON, one file per entry, filename = slug. A content edit is a
commit; a build consumes it. There is no sync step and no database.

Everything visible is editable in the CMS: entries, programs, contribution
categories, every photo, the logo and sharing image, navigation, the home
page's featured event and how many latest records it shows, fact sheets, links
and all interface text. Layout, colours and fonts stay in code.

Validate the CMS config whenever you change it:

```bash
bun run cms              # offline: structure, and field coverage vs content
bun run cms --schema     # ...plus validation against Sveltia's published schema
```

`bun run verify` also runs the offline checks. **If a field exists in `content/`
but is not declared in `public/admin/config.yml`, Sveltia drops it when an editor
saves** — the coverage check is what prevents that quiet data loss.

### 1. Editing locally (no auth, no server)

```bash
bun dev
```

Open <http://localhost:4321/admin/index.html> → *Work with Local Repository* →
select the repo root. Chromium only. (Astro's dev server does not map `/admin/`
to its `index.html`; production does.)

### 2. Editing in the browser with a token

A fallback if the OAuth worker is down:

1. Open <https://jnvckm.org/admin/>
2. Choose *Sign in with GitHub*
3. Follow the token link, or create a fine-grained token with **Contents: write**
   on `hamb1y/jnvckm`
4. Paste it in

Only people with write access to the repository can save, whatever the scope.

### 3. Editing in the browser with OAuth (the worker)

This is live: the worker runs at <https://auth.jnvckm.org> and `backend.base_url`
points at it. Editors open <https://jnvckm.org/admin/> and sign in with GitHub.
The steps below are how it was set up, for rebuilding it.

```bash
bun run cms:worker https://<worker-url>   # after step 4, verifies the contract
```

1. **Deploy the worker**

   ```bash
   git clone https://github.com/sveltia/sveltia-cms-auth
   cd sveltia-cms-auth
   npm install
   npx wrangler deploy
   ```

2. **Set its environment**

   ```bash
   npx wrangler secret put GITHUB_CLIENT_ID
   npx wrangler secret put GITHUB_CLIENT_SECRET
   ```

   And in that project's `wrangler.toml`:

   ```toml
   [vars]
   ALLOWED_DOMAINS = "jnvckm.org,www.jnvckm.org,jnvckm.pages.dev"
   ```

   `ALLOWED_DOMAINS` holds bare hostnames, comma-separated, with no scheme.
   Include every hostname the admin is served from, or sign-in fails with
   `UNSUPPORTED_DOMAIN`. The `jnvckm.pages.dev` hostname comes from the Pages
   project name.

3. **Create the GitHub OAuth app**

   - Homepage URL: `https://jnvckm.org`
   - Authorization callback URL: `https://<worker-url>/callback`

4. **Verify the worker before trusting it**

   ```bash
   bun run cms:worker https://<worker-url>
   ```

   It checks the three things that actually break: an allowed hostname must get
   a `302` to `https://github.com/login/oauth/authorize` carrying a real
   `client_id` and a `state`; a hostname that is *not* in `ALLOWED_DOMAINS` must
   be refused; and `/callback` must exist. A hostname is passed as `site_id`,
   not a URL. This is the step that catches an unset secret or a missing domain
   before an editor does.

5. **Point the CMS at it** — set `backend.base_url` in
   `public/admin/config.yml` to the worker origin, then run `bun run cms`.

per-language blocks. Old `/kn/…` addresses redirect to the English pages
(`public/_redirects`).

## Deploy

Cloudflare Pages, Git integration on `main`. There is no separate CI pipeline:
Pages already builds on every push, so the type gate lives in the build command.

- Build command: `bun run check && bun run build`
- Output directory: `dist`
- Environment: `BUN_VERSION` pinned (currently `1.4.2`)
- Project name `jnvckm` (this determines `jnvckm.pages.dev`)

Canonical URLs come from `site` in `astro.config.mjs` (`https://jnvckm.org`).
No `BASE_PATH`: the site is served from a domain root, so no base-prefixing
helper is needed.
